# Exclusions — RNC disposition ledger

This ledger is the **single exclusion authority** for `_backlog/categories/` active candidate registers. An **RNC exclusion** removes an independent review slot because it is obsolete, superseded by an identified replacement, or closed by a documented scope exception. It does **not** close an upstream GitHub issue/PR, assert adoption, or prove the underlying defect is resolved. Never edit upstream GitHub issue state automatically.

### Exclusion contract

- Canonical IDs: every upstream item in **both** exclusion tables above, with `upstream_issue:gitleaks/gitleaks#N` or `upstream_pr:gitleaks/gitleaks#N` namespace. The original seven IDs (#1939, #1435, #1960, #1991, #1959, #1103 and #2103) remain excluded; the second-pass table extends that set.
- Linked issue #1432 was already **closed upstream** and is not present in the open-issue inventory; it is contextual evidence for PR #1435, **not** a second RNC-closed work item.
- Exclude these items from all active category tables; reference this ledger instead. These PRs are **superseded**, not adopted or corrected by RNC. Docker-only supersession is scoped to the separately maintained hardened branch and does not establish release-wide CVE clearance.
- Do not use the upstream GitHub `state=open` as a reason to reinstate an RNC-closed issue automatically.
- A closure needs: an RNC disposition, precise scope, artifact/commit or image digest, evidence, and an explicit reopen trigger. “Resolved in RNC” does not mean “fixed upstream.”
- When refreshing the CSV or JSON snapshots, preserve the closure decision in a **separate reviewed-dispositions layer**. The raw upstream metadata remains immutable.

**Follow-up evidence improvement:** capture the exact current binary/image digest and a reproducible scan showing the two reported issue-specific CVEs absent. That will upgrade this from owner-confirmed closure to scan-attested closure without changing its current RNC disposition.
