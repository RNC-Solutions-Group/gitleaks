## Cross-cutting release constraints

1. **Never break exit status.** Gitleaks' leak-detected nonzero status must pass through every wrapper (npm, shell, PowerShell, CI) unchanged. A scan that detects secrets and exits successfully is a **security regression**, not a convenience bug.
2. **Separate publication integrity layers.** Docker build provenance (default on public repos), SBOM (#2220), image signatures (#1217), and installer release-asset verification (#1485) are distinct controls. Test each against actual published digests/assets; building a valid image does not prove consumers can verify it.
3. **Never assume upstream-repo-only CI runs in this fork.** PR #2209 retains the hard-coded upstream guard. Require visible, meaningful scanner checks without exposing license/registry/secrets to untrusted PR code.
4. **Release regex behavior differs from an untagged developer build.** Validate `gore2regex` memory/address-space constraints (#2017), finding parity, and predictable failure statuses using representative published binary builds; a dependency's lazy initialization is not the same as scanner safety.
5. **Cross-platform means user-path and architecture reality.** Exercise Windows/PowerShell, Linux, macOS, WSL/MSYS, paths containing whitespace, architecture exclusions, and both registries. Avoid silently declaring unsupported platforms safe.
6. **Proposed patches are not adopted code.** None of the six upstream PRs is merged into RNC `master`; statuses concern review and future implementation design only.
