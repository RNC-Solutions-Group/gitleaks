## OOM investigation crosswalk for issues 2019 and 1572

**Source inspection:** 2026-11-09 against fork `master` `5f6ec56cfa6f`. These are **separate work packages**, not duplicate reproductions. Neither claimed OOM was executed or independently reproduced during this documentation review.

| Boundary | [#2019](https://github.com/gitleaks/gitleaks/issues/2019) — recursive decoding | [#1572](https://github.com/gitleaks/gitleaks/issues/1572) — untrusted ignore input |
| --- | --- | --- |
| Entry and trigger | Ordinary Git scan of large history containing encoded content; CLI default decode depth 5 | Repository-controlled `.gitleaksignore` may be a symlink to a special/unbounded stream; reporter specifically described `/dev/random` |
| Source path | `cmd/root.go` flag → `detect/detect.go:Detect` decoding loop → `detect/codec/decoder.go:Decode` | `cmd/root.go:fileExists` (`os.Stat` follows links) → `detect/detect.go:AddGitleaksIgnore` (`os.Open`, `bufio.Scanner`, map inserts) |
| Allocation/error concern | New decoded buffers, cached decoded strings, multiple passes; size guard at `detectRule` is reached after decode work | No regular-file/symlink rejection or aggregate byte/entry budget; each nonblank, noncomment line is stored, including malformed entries; `scanner.Err()` is not checked |
| Control that is **not** a full fix | `--max-decode-depth=0` removes decode coverage; `MaxTargetMegaBytes` does not prevent earlier decoder allocations | Disabling directory-scan `--follow-symlinks` does not govern the separate ignore-file loader |
| Primary assessment owner | **CP3 / Performance & Stability**, with correctness parity in CP2 | **CP4 / Security & Hardening**, with input/failure semantics in CP2 |

**Evidence and important distinctions:**

1. Pinned [`cmd/root.go`](https://github.com/RNC-Solutions-Group/gitleaks/blob/5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c/cmd/root.go) defines `--max-decode-depth=5`, while [`detect/detect.go`](https://github.com/RNC-Solutions-Group/gitleaks/blob/5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c/detect/detect.go) passes decoded text back into rule evaluation. [`detect/codec/decoder.go`](https://github.com/RNC-Solutions-Group/gitleaks/blob/5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c/detect/codec/decoder.go) owns decoded-buffer allocation and per-decoder cache. This establishes plausible allocation growth, **not** a measured 24 GB defect or a proven exact root cause.
2. Ignore-file lookup and loading follow an independent path. `fileExists` uses `os.Stat`; `AddGitleaksIgnore` opens the target and reads entries into `d.gitleaksIgnore` with no aggregate limit, then returns nil without checking `scanner.Err()`. The general directory walk in [`sources/files.go`](https://github.com/RNC-Solutions-Group/gitleaks/blob/5f6ec56cfa6f8c67648d863582c7ae2f206d5c1c/sources/files.go) has its own symlink flag; it does **not** secure the ignore loader. #1572's upstream maintainer indicated willingness to accept a fix, not that one shipped. Canonical security disposition remains in [Security & Hardening](security-hardening.md).
3. The ordinary tracked symlink fixture `testdata/repos/symlinks/file_symlink/symlinked_id_ed25519` links to a regular test file and is **not** #1572's hostile `.gitleaksignore` case. Its disappearance in some linked worktree/Windows checkouts is a **fixture availability** issue: CP0 must verify file mode, actual host symlink and supported test execution; CP2 must label tests skipped/unsupported rather than falsely passing or treating the fixture failure as OOM evidence.

**Safe reproduction matrix for later authorized checkpoints:**

- For #2019, use finite, synthetic, encoded Git/dir corpora with a recorded dataset hash, fixed worker concurrency, and depths **0/1/3/5**. Measure peak resident memory (not only post-GC heap), CPU, allocations, duration, findings, errors and process exit; compare detection coverage as well as memory. Keep process memory/time limits explicit.
- For #1572, use only disposable **finite** newline-delimited synthetic ignore files, including a controlled symlink, malformed records and bounded-size growth. Assert regular-file policy, input/entry ceilings, scanner-error propagation, and fail-closed status. Run under isolated process/container resource limits; **never** use `/dev/random`, another unbounded device, real credentials or production repository contents as the reproducer.
- Keep results and dispositions separate. Both upstream OOM claims are **unverified at runtime** on this fork; no tests or scanner changes were made in this backlog review.

## Recommended sequence

1. **Scan completeness:** V11/V12 corrected Git process/drain, parser-section and unsupported-format fail-closed behavior. Retain the regression suite; do not reopen without a new false-clean reproducer.
2. **Regex reuse:** V12 adopted the single-scan match reuse and recorded benchmark evidence. Keep parity/performance tests; no further optimization is authorized without new measured need.
3. **Protect detection behavior — #2023:** evaluate newline caching separately from regex reuse and size-limit semantics; reject any change that silently suppresses path-only findings or weakens encoded scanning.
4. **Memory profiling — #2019:** collect bounded, repeatable workload profiles and distinguish peak RSS from post-GC in-use heap. The README default mismatch has a separate Documentation owner; it is not the memory fix.
5. **Reliable measurements — #1900:** make benchmark and diagnostic flags identical, prevent a finding from prematurely aborting profiles, then test cross-platform shell prerequisites.
6. **Root cause before disposition — #1437:** request a contemporary stack/reproducer; no closure or duplicate inference from age or futex alone.
