## Recommended sequence

1. **Scan completeness first — #1338 / #2246:** prove a malformed/truncated Git stream results in a nonzero CLI/CI status, not only an error log. Test parser/pipe deadlock, malformed tail with no unread bytes, cancellation and exit-code propagation end to end.
2. **Low-scope performance gain — #2121 / #2271:** test the one-line match reuse on positive and negative fixtures; measure CPU/allocations before expanding the patch surface.
3. **Protect detection behavior — #2023:** evaluate newline caching separately from regex reuse and size-limit semantics; reject any change that silently suppresses path-only findings or weakens encoded scanning.
4. **Memory profiling — #2019:** collect bounded, repeatable workload profiles and distinguish peak RSS from post-GC in-use heap. The README default mismatch has a separate Documentation owner; it is not the memory fix.
5. **Reliable measurements — #1900:** make benchmark and diagnostic flags identical, prevent a finding from prematurely aborting profiles, then test cross-platform shell prerequisites.
6. **Root cause before disposition — #1437:** request a contemporary stack/reproducer; no closure or duplicate inference from age or futex alone.

## Completion gate

- Pin the fork commit, upstream PR head, Go and Git versions, platform, flags, dataset manifest/hash, decode depth, worker concurrency, and exact test commands.
- Compare **expected findings, scan coverage, errors, exit codes, peak RSS, allocations and elapsed time**. A faster scan that silently omits work is a regression.
- Re-run upstream Go tests plus targeted CLI, Git/dir, required-rule, decoded-content and parser-failure fixtures. Keep synthetic test secrets only and avoid emitting real credential samples.
- Only call a change **adopted** with its upstream attribution and the actual RNC integration PR/commit and passing evidence; **corrected** requires an RNC-origin implementation. No upstream issue/PR or fork `master` is changed by these documents.
