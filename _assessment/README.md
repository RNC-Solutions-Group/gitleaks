This directory hosts reproducible assessment work for the Gitleaks fork on `feat/issues-and-pr`. It is deliberately separate from the owner/GPT-managed [`_backlog/`](../_backlog/README.md). The backlog catalogs upstream issues, PRs, crosswalks, and dispositions; the assessment documents **what our actual code does**, its measured baseline, and how proposed changes might interact with it.

## How to work

1. **Cold start:** identify repository, branch, commit, instructions, and objective; report understanding only.
2. **Explicit activation:** Dave requests a named checkpoint (for example, `Execute CP0`). Read its assignment and investigate only its scope.
3. **Evidence:** cite actual source paths/functions, Git SHAs, commands and exit codes, tests, external links, and measured conditions. Separate verified, measured, inferred, and unverified findings.
4. **Documentation:** write the report and supplementary evidence only to `_assessment/` and update this index when needed. Redact secret-like data, even from intentionally seeded fixtures.
5. **Checkpoint review:** summarize findings, omissions, and recommended next steps; await a new instruction. Completion does **not** authorize the next checkpoint.

## Shared definition of done

A checkpoint is ready for owner review only when:

- [ ] Its exact scope and every required deliverable are addressed, or omissions are explicitly explained.
- [ ] Repository, branch, assessed commit SHA, environment, and timestamp are recorded.
- [ ] Significant findings distinguish **verified / measured / inferred / unverified** and provide reproducible evidence.
- [ ] Commands, tool versions when relevant, exit status, benchmark inputs, and limitations are documented. Tests that were not run are labeled **not run**, never passed.
- [ ] Existing issues are separated from hypothetical regressions; observed behavior is separated from expected behavior.
- [ ] No protected source/configuration/test files were intentionally modified. Pre/post working-tree status is recorded, and unexpected differences are reported without unapproved cleanup.
- [ ] The report identifies remaining questions, risk/impact, and readiness for the next checkpoint.
- [ ] The agent has stopped and is awaiting owner review or authorization.

The purpose is **accurate characterization**, not making the baseline look healthy. A failed test, a missing tool, or an unresolved architectural question is useful evidence when described honestly.

## Baseline and future external PR reviews

CP0–CP5 will establish the technical baseline before cross-repository comparisons. Later comparisons must evaluate an external PR against **our pinned baseline and current code**, not assume the PR is right, wrong, or applicable. Assess applicability, technical correctness, compatibility/regression risk, and measurable value separately. A mismatch with our baseline is a finding, not proof the external PR is defective.
